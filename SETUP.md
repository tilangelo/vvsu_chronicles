# Запуск и рабочая среда

Актуально: 2 ноября 2026. Здесь описана версия, реально использованная в проекте; это не утверждение о последнем доступном релизе движка.

## Обязательное для запуска на Windows

**Godot 4.7.2 Standard, GDScript, Compatibility.** Проверенная версия консоли: `4.7.2.stable.official.ed1daf0bf`. .NET SDK, Node.js и отдельные пакеты Python для игры не требуются.

На текущем компьютере движок находится здесь:

```text
C:\Users\angelo\Desktop\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe
```

На другой машине путь будет отличаться. Движок не обязан быть добавлен в PATH.

1. Открыть менеджер проектов Godot и импортировать `game/project.godot` из основной папки проекта.
2. Дождаться импорта ресурсов.
3. Нажать F5, в меню выбрать «Начать».
4. Проверить часы 12:40, баланс 500 ₽ и три строки заданий.

Не импортировать демонстрационные проекты из `assets/godot_4_7` или пакета обновления: их код и карты отличаются от активной игры. F6 запускает текущую сцену и может обойти главное меню; для обычного запуска использовать F5.

## Для разработки

| Инструмент | Статус |
|---|---|
| Godot 4.7.2 Standard | Обязателен для запуска и проверки |
| Git | Рекомендуется для истории и совместной работы; для запуска не обязателен |
| VS Code + Godot Tools | Необязательный внешний редактор; встроенного редактора Godot достаточно |
| LibreSprite или Aseprite | Нужен художнику для изменения исходников .ase; для запуска PNG не нужен |
| PowerShell | Для команд и сбора доказательств; на этом компьютере уже доступен |

Python/Poppler использовались агентом для просмотра PDF/подготовки материалов. Это инструменты обработки документации, не зависимости Godot-проекта. Дополнительные редакторы звука/3D/офисных файлов устанавливаются только по конкретной задаче.

## Проверка из командной строки

В PowerShell из корня проекта, с исправленным под свой компьютер путём:

```powershell
$godotExe = 'C:\Users\angelo\Desktop\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe'
& $godotExe --version
& $godotExe --headless --path '.\game' --editor --import --quit
& $godotExe --headless --path '.\game' --script res://tools/check_day_quests.gd --quit-after 600
```

Полный воспроизводимый прогон с журналами:

```powershell
& '.\docs\collect_evidence.ps1' -GodotPath $godotExe -OutputDirectory '.\docs\verification\latest'
```

Описание покрытия и уже сохранённые результаты: [docs/VALIDATION.md](docs/VALIDATION.md). Успех импорта сам по себе не заменяет проверку игровых сценариев.

## Экспорт и Batocera

Готовая экспортированная сборка не является текущим результатом. В активной папке `game/` нет настроенного `export_presets.cfg`; экспорт не проверен.

Когда потребуется отдельная сборка, понадобятся export templates **той же версии**, профиль нужной платформы и включение JSON-данных в экспорт (`*.json`). Перед проверкой Batocera необходимо уточнить устройство/версию системы, способ запуска Linux-приложения, разрешение экрана, оси и кнопки аркадного контроллера.

Работа Windows-версии и наличие привязок ввода не подтверждают совместимость с Batocera.
