# Документация проекта

Состояние: **2 ноября 2026**, рабочий Windows-прототип. Отправная точка для отчёта — **[REPORT_GUIDE.md](REPORT_GUIDE.md)**; для продолжения разработки — [CONTEXT.md](../CONTEXT.md).

## Приоритет сведений

Фактический код/данные в game/ и результаты его проверок → актуальные документы ниже → старые планы и инструкции в исходных пакетах. Если документ расходится с кодом, не подгонять результат отчёта под документ: зафиксировать расхождение и перепроверить.

Документы из assets/ описывают исходный замысел или демонстрационные наборы. Их фразы «NPC отсутствуют», «пять карт», «гардероб пока не нужен» и инструкции запуска пакета **не описывают активную игру**.

## Исходные и исторические документы

Полный реестр находится в [assets/README.md](../assets/README.md). Сохранены оригинальные:

- assets/maps/plan_1_floor.md — подписи пользователя к рисункам;
- assets/план/ПЛАН_МАРШРУТА.md — план, референсы и допущения автора набора;
- assets/iso_64x32/README.md — документация первой поставки;
- assets/ВВГУ_обновление_люди_интерфейс_анимация/ИНТЕГРАЦИЯ.md;
- одноимённая инструкция в подпапке godot_4_7/ и README.md в iso_64x32/ пакета обновления;
- УДАЛИТЬ_СТАРОЕ.txt — заметка поставки, не актуальное поручение на удаление;
- презентация sources/Хроники_Кампуса.pptx и PDF поставок.

Эти источники не переписывались под новый код: их исходное содержание нужно для происхождения решений и графики. Проверять их утверждения о готовности по текущему game/.

## Поддержание актуальности

При изменении логики обновлять GDD, FEATURES, ARCHITECTURE и CONTEXT по затронутым пунктам; при изменении среды — SETUP. После существенных изменений заново собрать evidence в новый каталог, подписать новые скриншоты и сверить цифры. Не выдавать старый снимок проверок за проверку нового кода.

В отчёте ссылаться на конкретный файл/функцию или журнал. Возраст снимка и его captured_at видны в JSON; у проверенных runtime-файлов есть хеши. Если нужны учебный шаблон, реквизиты, состав команды и объём отчёта, их следует получить отдельно — в проекте эти сведения не определены.
